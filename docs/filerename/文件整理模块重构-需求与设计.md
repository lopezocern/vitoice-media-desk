# 文件整理模块重构 · 需求与设计（PRD + Technical Design）

> 状态：**待用户确认**
> 范围对象：MediaDesk「文件整理」模块（现 `app/ui/rename_page.py` + `app/renamer.py`）
> 依据：用户提供的 10 张规则驱动批量重命名器截图（EA 系媒体库重命名界面，深色主题） + 需求对齐结论
> 目标形态与主题：**复刻截图交互形态**，沿用 MediaDesk **浅色主题**

---

## 1. 背景与目标

现有「文件整理」模块只是**单一用途**工具：给中文名加拼音首字母前缀重命名 + 清理垃圾文件。
用户需要将它升级为**规则驱动的通用批量重命名器**：一次扫描批量文件，通过「查找替换 / 组合命名模板 / 删除字符 / 转换 / 设置扩展名」等规则生成新文件名，并在落地前**逐行实时预览**「原名称 → 转换后名称」。

### 目标
1. 把重命名能力从「一种内置方案」升级为「一套可组合的规则引擎」。
2. 提供与截图一致的「左配置 + 右实时双列预览」工作流，但落在 MediaDesk 浅色主题上。
3. 保持全程**干跑预览、确认后落地**的安全心智（现有模块的核心安全设计）。
4. 不破坏已有的其他模块。

## 3. 范围定义

### 3.1 In（本轮纳入）
- 左侧规则配置面板 + 右侧「原名称 → 转换后名称」实时双列预览表格。
- 五种规则操作：查找替换、组合命名模板、删除字符、转换、设置扩展名。
- 变量模板：`${original}`、`${folder}`、`${create_time:fmt}`、`${modify_time:fmt}`、`${seq:start;increment;padding}`、`${random:N}`、`${uuid}`。
- 通用选项：保留扩展名（默认勾选）、只更改现有扩展名、使用正则、忽略大小写、全部替换。
- **拼音前缀重命名保留为「组合模板」内置预设**；**垃圾文件清理保留为独立动作**（沿用现有 `JUNK_PATTERNS`）。
- 文件列表：扩展名/名称过滤、交替行、变化行高亮、**新名冲突标红**（**不做图片缩略图**，纯文本列表）。
- 冲突检测与落地前二次确认。

### 3.2 Out（本轮不纳入）
- **标签名、来源网站、导入时间变量**（依赖媒体标签/元数据，无数据源）——功能不实现，但「组合模板」中的对应**按钮保留入口**，点击提示「暂无数据源」，不误导用户。
- 真正的「媒体库 / 导入时间」概念（`import_time`）——无库，故不实现；仅实现文件系统可得的 `create_time` / `modify_time`。
- 跨多目录选择来源文件（沿用「扫描一个目标目录」的既有交互，范围之外待定）。
- 规则预设的持久化存储（可预留接口，落库留待后续）。

## 4. 用户故事

- 作为用户，我导入一批命名混乱的文件后，能选一条规则（如正则查找替换、按模板加序列号），在下方的表格里**立刻看到每个文件会变成什么名字**。
- 我想给一批照片统一改成 `日期 + 序号`：用组合模板 `${create_time:yyyy-MM-dd}_${seq:start=1;increment=1;padding=3}`，预览确认后应用。
- 我想把一批 `Z 张韶涵_P_###.jpg` 统一改小写、或只替换其中一个词，保留扩展名。
- 我想删除文件名前几个字符，或统一改扩展名。
- 我想继续用老的「中文名加拼音前缀」和「清理 Thumbs.db 等垃圾文件」。

## 5. 功能需求

### 5.1 交互总览
- 顶部：目标目录选择（沿用现有「目录输入 + 浏览」）+「扫描/刷新」。
- 主体分左右两栏（浅色主题）：
  - **左：规则配置面板**（宽度约 280–320px）——操作类型下拉 + 随操作联动的参数区 + 通用选项。
  - **右：文件预览表**——表头 `原名称 → 转换后名称` + 过滤栏；逐行实时预览；落地按钮。
- 底部：统计（共 N 项 · 将变化 M 项）+「重置规则 / 应用更改」。
- 流程：选目录 → 扫描加载文件 → 改规则（实时预览刷新）→ 应用（二次确认）→ 落地。

### 5.2 规则操作 FR

#### FR-1 查找替换
- 输入：查找文本、替换文本。
- 选项：使用正则表达式、忽略大小写、全部替换。
- 逻辑：对名称主名（保留扩展名时不含扩展名）做替换；`全部替换` 打开时替换所有匹配，否则只替换首个。
- 正则无效时：预览列对应行标红并提示（不阻塞其他行）。

#### FR-2 组合命名模板
- 输入：「名称（不含扩展名）」模板文本框 + 变量快速插入按钮（原名称 / 文件夹名称 / 日期时间 / 序列号 / 随机字符串 / 随机 UUID）。
- 模板中可混写普通文本与 `${变量}`；空模板则报无输出（标红）。
- **内置预设**：「拼音前缀」一键填入 `拼音首字母 + 原名称`，复刻现有 `renamer.plan_rename` 行为。

#### FR-3 删除字符
- 输入：起始位置、删除字符数、计数起点（开头 / 末尾）。
- 逻辑：按起点定位后删除指定字符数；越界时安全截断。

#### FR-4 转换
- 下拉选择：改为小写 / 改为大写 / 标题式大写 / 首字母大写 / 移除特殊符号(äé→ae) / URL 解码。
- 作用于主名；保留扩展名时扩展名不参与且不受影响。

#### FR-5 设置扩展名
- 输入：新扩展名文本 + 勾选「只更改现有扩展名」。
- 逻辑：统一改为新扩展名；「只更改现有扩展名」勾选时仅对已有扩展名的文件生效（文件本身带扩展名），无扩展名文件不改。
- 新扩展名使用指定值；取消「只更改现有扩展名」时可理解为“增加/设置扩展名”。

### 5.3 变量模板语法

| 变量 | 说明 | 示例输出 |
|---|---|---|
| `${original}` | 原主名（不含扩展名） | `Z 张韶涵_P_019` |
| `${folder}` | 所在父目录名 | `2026_活动` |
| `${create_time:fmt}` | 文件创建时间（系统生时/元数据可得） | `${create_time:yyyy-MM-dd}` → `2026-09-11` |
| `${modify_time:fmt}` | 文件修改时间 | `${modify_time:yyyy-MM-dd_HH-mm-ss}` |
| `${seq:start=1;increment=1;padding=3}` | 按文件顺序编号 | `001`,`002`,`003` |
| `${random:N}` | N 位随机字符串 | `${random:6}` → `a3f9x2` |
| `${uuid}` | 随机 UUID | `6f9c…` |

- 时间格式标记与截图一致：`yyyy / MM / dd / HH / mm / ss`。
- 未支持/拼写错误变量：该行标红并在预览表给出原因。
- 序列号按文件在列表中的**当前排序顺序**递增；padding 为总位宽（0 填充）。

### 5.4 通用选项
- **保留扩展名**：默认勾选。勾选时扩展名从主名中隔离，规则只作用主名，落地前再拼回原扩展名（查找替换/转换/删除 均生效）。
- **只更改现有扩展名**（FR-5 专用）。
- **使用正则 / 忽略大小写 / 全部替换**（FR-1 专用）。

### 5.5 内置能力保留
- **拼音前缀预设**（FR-2）：复刻 `renamer.plan_rename` 的「中文开头才加」「已英文/序号开头跳过」逻辑。
- **垃圾清理**：独立动作（面板底部「清理垃圾文件」），沿用 `renamer.JUNK_PATTERNS` 与二次确认，删除项在预览表中以醒目方式展示并需单独确认。

### 5.6 实时预览与安全
- 规则参数任一变化 → 防抖（约 120ms）重算所有行新名，仅更新有差异的行，避免大目录卡顿。
- 新名与原扩展名冲突 / 同行重名 / 与列表内其他文件重名 → 该行整行标红 + 顶部提示「N 项冲突」。
- 「应用更改」前二次确认，展示「将变化 M 项」；采用现有「重命名先、清理后」顺序。
- 落地沿用 `plan.accept()`，`PermissionError` 静默跳过并计入失败提示。

## 6. 界面设计（浅色主题）

布局（对齐各功能页现有风格：页面头 + 段落小竖条标题 + 圆角卡片）：

```
┌────────────────────────────────────────────────────────────┐
│ 文件整理                          [副标题]                    │
├───────────────────────────────┬────────────────────────────┤
│ ▍规则配置                      │ ▍文件预览                    │
│ ┌───────────────────────────┐ │ ┌─────────┬────────────────┐│
│ │ 操作类型 [查找替换 ▾]      │ │ │ 🔍过滤   [全部▾]          ││
│ │ 查找 [________]           │ │ ├─────────┼────────────────┤│
│ │ ☐正则 ☐忽略大小写 ☑全部替换 │ │ │▶原名称  → 转换后名称      ││
│ │ 替换 [________]           │ │ │┌─────────────────────────┐││
│ │ ☑保留扩展名               │ │ ││ [缩略] 图像-(4).jpeg → 图像 ││
│ │ [重置][复原]              │ │ ││        -(4).jpeg         ││
│ └───────────────────────────┘ │ ││[缩略] Z 张韶涵.. → z__..  ││
│ [清理垃圾文件]                 │ │└─────────────────────────┘│
├───────────────────────────────┼────────────────────────────┤
│ 共 33 项 · 将变化 12 项 · 冲突 0  [重置规则]  [应用更改]        │
└───────────────────────────────┴────────────────────────────┘
```

- **预览表**信息密度与截图一致：缩略图列 + 原名称列 + 转换后名称列；转换后名称高亮差异；未变化行显示 `→`，变化行显示新名。
- 过滤栏：按扩展名分群（全部/图片/视频/音频/其他）+ 名称关键词过滤。
- 主题：沿用 MediaDesk 设计令牌（`#4f5bd5` 主色、浅色工作台、9/12 圆角、任务行渐变进度等），与四功能页一致。

## 7. 架构与技术设计

### 7.1 目录与职责
```
app/filerename/            # 规则引擎（纯 Python，可单测，无 Qt 依赖，干跑友好）
├── __init__.py
├── variables.py           # ${...} 变量解析与渲染（original/folder/时间/seq/random/uuid；拼音预设）
├── ops.py                 # 5 类操作：find_replace / compose_template / delete_chars / transform / set_ext
└── engine.py              # 编排：load_items(dir) → apply_rule(items, op, opts) → render one name (纯函数)；
                           # get_seq 依排序分配；冲突检测；输出 PendingItem 列表

app/ui/rename_page.py      # 重写：左配置面板 + 右双列预览表 + 过滤 + 实时防抖渲染 + 落地
app/renamer.py             # 保留 Plan / JUNK_PATTERNS / apply_plans，供引擎落地与清理复用
```

### 7.2 数据模型
```
@dataclass
class RuleOperation(enum): FIND_REPLACE, TEMPLATE, DELETE_CHARS, TRANSFORM, SET_EXT

@dataclass
class RuleConfig:
    operation: RuleOperation
    find / replace / regex / ignore_case / replace_all      # FR-1
    template / seq 参数 / random 长度                        # FR-2
    start / count / from_end                                # FR-3
    transform_kind                                          # FR-4
    ext / only_existing                                     # FR-5
    keep_ext: bool = True

@dataclass
class FileItem:            # 扫描得到
    path: Path
    stem: str              # 主名（不含扩展名）
    ext: str               # 扩展名（含 .）或 ""
    ctime / mtime

@dataclass
class PendingItem:         # 预览每行
    item: FileItem
    new_name: str          # 目标全名
    changed: bool
    note: str = ""         # 变量错误/冲突原因（空=正常）
```

### 7.3 关键逻辑
- **预览为纯函数**：`render_one(item, rule) -> (new_full_name, note)`。方便单测与惰性渲染。
- **实时渲染防抖**：参数变化 → `QTimer.singleShot(120ms)` 重算；渲染时逐行 diff，仅替换变化行的 label。
- **序列号**：先对当前列表排序，再按序展开 `seq` 到各项（池化分配，保证唯一递增）。
- **保留扩展名**：`render_one` 内部先取 stem 处理，落地时再拼 `ext`（`keep_ext=True`）。`SET_EXT` 例外：改写 ext。
- **冲突检测**：同一 `new_name` 出现两次 → 相关行共同标红；与 `keep_ext` 后结果重复同样检测。
- **落地**：把 `PendingItem` 转 `Plan(old, new, kind, note)` 交 `renamer.apply_plans`（重命名先、清理后）。清理项沿用 `fill`（unlink）。

## 8. 非功能需求
- **纯 Python 引擎可单测**：变量语法、各操作、序列分配、冲突检测给出用例。
- **性能**：500 文件规模下，单次规则变更预览重算 ≤ 250ms（防抖后），不阻塞 UI。
- **安全**：落地前二次确认；删除动作单独确认；`PermissionError` 不中断整体。
- **无障碍/统一**：Hover 有主色反馈、键盘可操作；样式对齐既有设计令牌。
